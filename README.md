# CARDKKKKKK

Unity 2022.3.62f3c1 单机卡牌项目。原自由牌桌保留生成、选择、拖动、堆叠、排序、洗牌、翻面、整理和存档。左上角“测试玩法”进入独立的法术拆装试炼，返回后恢复原牌桌。

“测试玩法”右侧新增“孤岛生存”入口，接入独立准备场景，当前仅显示“开发准备中”和“返回牌桌”，尚无生存规则。运行CardTableDemo，点击“孤岛生存”；点击“返回牌桌”或Esc回到原桌面。源场景为Assets/IslandSurvival/Scenes/IslandSurvival.unity，模块与法术玩法隔离。入口已做静态接线检查，编译与实际进入/返回待用户在Unity确认。

孤岛方案、实际实现边界和阶段目标见[完整设计](docs/design/孤岛桌面生存-完整设计.md)及[完成度与分阶段开发计划](docs/design/孤岛生存-完成度与分阶段开发计划.md)。设计成熟度约75%为工程判断；可运行生存玩法尚未交付，不能把入口准备计成主体完成。

开发分工见[孤岛生存需求表](outputs/01a1aae4-8672-7cd2-8fde-a44094785f06/孤岛生存-开发需求表.xlsx)：21个系统、62条程序/策划/美术需求、30项策划配置合同、46项美术资源需求及6阶段验收。程序须交付中文配置、校验和实际生效能力，策划通过资产配置内容与数值，美术通过稳定资源引用接入；三方进度和运行验收分别记录。

当前玩法由用户选择的“拆开并重组法术规则”发展而来：[玩法发散记录](docs/design/玩法发散-2026-11-05.md)、[法术拆装实现说明](Assets/TestGameplay/Spellcraft/README.md)。旧八配方工坊与河谷营地方案停用，旧工坊源码、配置和场景已清理，历史版本可查303ce22；旧图片仅留档。

## 测试玩法

运行原来的 CardTableDemo 场景，点击左上角“测试玩法”。原牌桌对象暂停并保留；新场景有自己的装置、牌组、战斗进度和独立存档，点“返回牌桌”恢复原来的牌和位置。默认运行入口仍是原牌桌。

开局有三个装置槽。点击装置，从零件牌中选择“触发→效果→改装”，点“装上”；再点“进入试炼”。战斗中先选敌人，再使用手牌或手动装置，最后结束回合。自动装置在受伤、挡击、消耗火花等条件发生时触发，每个装置每回合最多两次。悬停手牌或手动装置，可查看同一套规则计算出的完整连锁预演。

默认装配为手动启动→电击器、受伤触发→充能器、耗火花触发→护盾器。规则下第一次手动电击：消耗1能量与共3火花，造成4直伤，并连锁获得8护盾；预演能在执行前展示。此处是规则说明，不是助手实际运行结果。四场遭遇依次加入防御、反弹、抽火花、蓄力重击；前三场胜利各选一个新零件，并回装配台改造。

选择“测试玩法 > 法术工坊规则”编辑规则，或打开 Assets/TestGameplay/Spellcraft/Configuration/法术工坊配置.asset。中文 Inspector 可配置生命、能量、火花、触发上限、零件强度与消耗、牌组、敌人行动、奖励和插画。当前界面支持三装置、最多五手牌、三敌人、三个奖励选项，越界配置明确拒绝。

测试存档位于 Application.persistentDataPath/TestGameplay/spellcraft-v1.json；每次成功操作和返回时自动保存，下次进入继续。修改数值、解锁、牌组等规则后拒读旧规则存档并暂停自动覆盖，手动保存或重新开始才恢复；显示名称、说明或插画调整不再使新版存档失效，本次改名前的法术存档保留兼容读取。Q/W/E启动装置，1～5出手牌，空格结束回合，回车确认焦点按钮；Esc关闭拆装页或开关菜单。保存、读取、重开和返回牌桌集中在菜单中。

界面以1600×900逻辑桌面整体等比缩放，卡片和字体保持相同比例；宽屏多出的区域显示背景。主桌面分为敌人、装置、手牌三层，拆装页独立显示，底层桌面隐藏。三列零件独立滚动，底部显示组合与完整规则；战斗预演保留在右侧，可滚动查看长内容。修改已经写入真实Prefab，停止当前Play后重新进入“测试玩法”即可加载。

代码、场景、Prefab、美术都在[测试玩法模块](Assets/TestGameplay/README.md)。SpriteCook余额为0，本次按授权使用内置image_gen生成原创16对象图集、背景和卡框，统一轮廓与色块，已绑定配置和编辑态Prefab。当前只做源码、配置与资源静态核对，没有编译或运行Unity。

## 从哪里开始配置

1. 打开项目，选择 `卡牌桌面 > 打开卡牌桌面`。场景已经放好真实的 Canvas 和界面 Prefab，编辑状态可见桌面与占位牌。
2. 选择 `卡牌桌面 > 游戏规则配置`。窗口默认读取当前场景启动器实际引用的配置，分为 **桌面规则、卡牌目录、初始桌面、功能与资源** 四页。
3. 修改后点击“检查配置”和“保存配置资产”，下一次运行时应用。修改运行中的配置资产不会直接改写当前桌面。
4. 默认资产是 `Assets/CardTable/Configuration/默认游戏配置.asset`。做另一套规则时复制它，在场景的 `CardTableDemo` 启动器上替换“游戏配置”引用。

游戏视图只留卡牌、短操作和当前状态。右上角问号打开快捷键，Esc 收起。没有常驻操作指南、开发路径或插画占位字。

| 想改什么 | 在哪里改 | 实际影响 |
|---|---|---|
| 一种新卡、名称、分类、序号、初始属性、插画 | 卡牌目录页“新建卡牌定义并加入目录”，然后编辑该定义 | 发牌列表、显示与实例生成都读这个定义 |
| 只许同种牌叠放 | 桌面规则 → 堆叠兼容方式 → 相同定义 | 拖放、自动合堆、整理及读档统一检查 |
| 不允许叠牌 | 桌面规则 → 关闭允许堆叠 | 每堆只能一张；初始桌面也须改成单张堆 |
| 整堆移动或只许拆单张 | 桌面规则 → 两个拖动权限 | 核心直接拒绝禁用的拖动方式 |
| 生成、整理时是否自动合堆 | 桌面规则 → 两个自动合并选项 | 分别控制生成重叠与整理合堆；不影响允许的手动拖合 |
| 排序方向 | 桌面规则 → 牌堆排序方式 | 序号升序、序号降序或名称升序，相同值保留原顺序 |
| 桌面、卡片尺寸与容量 | 桌面规则 → 桌面尺寸与容量 | 视觉尺寸、碰撞、吸附与合法性使用同一组规则 |
| 开局放什么牌、在哪里、叠放顺序 | 初始桌面 | 每项一堆，位置是底牌左下角，列表从底到顶 |
| 去掉翻面、洗牌、整理等功能 | 功能与资源 | 取消勾选后界面和核心都禁止操作；可进一步从编译中移除 |
| 卡框、背景、字体、音效 | 功能与资源 → 美术与音频主题 | 复用主题；单张卡面在卡牌定义中配置 |

卡牌“初始实例属性”目前是可存取、可保存的数据，例如“能量 = 3”；不会自动变成费用、伤害或配方条件。这些含义要在选定玩法后由玩法代码定义。详细示例见 [配置与扩展说明](docs/configuration-guide.md)。

## 关闭功能与删除实现

翻面、排序、洗牌、堆内调序、抽牌、整理、存档分别是独立模块。取消勾选先改变本配置的可用能力；点击 **“应用功能裁剪到编译”** 才会用条件编译排除对应完整实现和调用点，重新开启也需再次点击。这个按钮会触发 Unity 正常脚本重载，作用于当前构建平台的整个工程；多个规则配置共用同一套编译裁剪。

| 功能 | 从编译中移除的实现 | 裁剪符号 |
|---|---|---|
| 翻面 | `Core/Operations/BoardEngine.Flip.cs` | `CARDTABLE_DISABLE_FLIP` |
| 排序 | `Core/Operations/BoardEngine.Sort.cs` | `CARDTABLE_DISABLE_SORT` |
| 洗牌 | `Core/Operations/BoardEngine.Shuffle.cs` | `CARDTABLE_DISABLE_SHUFFLE` |
| 堆内调序 | `Core/Operations/BoardEngine.Reorder.cs` | `CARDTABLE_DISABLE_REORDER` |
| 抽出顶牌 | `Core/Operations/BoardEngine.Pop.cs` | `CARDTABLE_DISABLE_POP` |
| 整理桌面 | `Core/Operations/BoardEngine.Tidy.cs` 及独占布局辅助代码 | `CARDTABLE_DISABLE_TIDY` |
| 保存与读取 | `Unity/BoardSaveStore.cs` | `CARDTABLE_DISABLE_SAVE` |

源码保留在对应文件中，方便以后恢复。编译裁剪会排除功能实现，不是只藏按钮。没有自动修改工程现有编译符号；仅在你点击按钮时管理上表七项，其他符号保留。基础的状态校验、拖放、碰撞和自动找空位仍是桌面底座。

这轮实际删除了旧演示的整段运行时 UI 生成器、固定三类发牌模板、重复刷新路径、主题里的重复卡面映射，以及玩家界面的“处理重叠”调试按钮和 O 快捷键。自动避让和非法重叠拒绝继续属于核心职责。

## 默认桌面与操作

默认规则：1600×900 桌面，100×140 卡片，单堆最多 20 张，全桌最多 1000 张，相同分类可堆叠。初始为藏书、物资、工具三堆，共九张牌。发牌列表来自配置中的全部九个定义，不再循环硬编码的序号。

| 操作 | 输入 |
|---|---|
| 选择并置顶 | 左键点击卡牌 |
| 移动整堆 | 普通拖拽 |
| 拆出单张 | 按住 Shift 拖拽 |
| 取消拖动 | Esc 或窗口失焦 |
| 翻面 | 空格 |
| 稳定排序 / 洗牌 | S / H |
| 抽出顶牌并找空位 | P |
| 堆内前移 / 后移 | 左 / 右方向键 |
| 整理桌面 | R |
| 保存 / 读取 | F5 / F9 |

关闭的功能不显示可用按钮，也不会响应对应命令。拖动时绿色预览表示可放，红色表示会回原位，插槽线标出入堆位置。正在布局动画或拖动时，其他修改会被拒绝。

默认运行场景已设为本桌面。需要调试其他场景时，选择 `卡牌桌面 > 运行时进入当前场景`；恢复入口选择 `卡牌桌面 > 运行时进入卡牌桌面`。

## 算法、存档与边界

核心先在候选副本上操作，通过规则与几何校验后一次提交；失败不改变已提交状态。预览与提交共用落点规划，拖动会话复用空间哈希索引。稳定排序 O(n log n)，Fisher–Yates 洗牌 O(n)。空位搜索最多 20000 个候选，整理使用容量约束并查集合堆与高度优先列布局；有限候选和启发式不保证全局最佳装箱，找不到位置时保留原桌面。

本轮支持 Windows、单鼠标、有限二维桌面、统一卡片尺寸、无旋转。暂未加入战斗、配方、委托、回合、胜负、联网或无限桌面。配置只展示已实现的规则。

存档位于 `Application.persistentDataPath/配置中的文件名`，默认 `card-table.json`，有效备份后缀 `.bak`。保存实例 ID、当前属性、翻面、牌序、位置与层级。静态名称、分类、序号读取时按当前定义重新解析，因此规则或定义变化可能使旧档不再合法，读取会整体拒绝。版本 1 格式保留；默认提供旧 `archive.sample / supply.sample / tool.sample` 序号 1～3 的迁移映射。旧演示额外生成的序号 4～9 需要补充对应卡牌定义及迁移字段，不能直接当作现有九种牌读取。

现有棕色卡面、花纹卡背和暗色桌面已接入默认主题，详见 [美术说明](Assets/CardTable/Art/README.md)。物件插画和音频暂缺，可以继续留空。
