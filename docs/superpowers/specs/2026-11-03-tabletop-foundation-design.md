# 卡牌桌面基础框架

## 目标与开发难度

按照用户两张需求截图，建立单机桌面卡牌交互框架。完整桌面交互属于中高难度，工作集中在牌堆变更、拖拽期间状态一致性、几何边界与存档恢复。美术以占位符和资源入口推进。

| 功能 | 难度 | 本轮边界 |
|---|---|---|
| 生成、选中、置顶、翻面 | 低 | 单个鼠标指针，统一卡片尺寸 |
| 牌堆移动、抽单张、插牌、重排 | 中高 | 牌堆从底到顶排序，Shift 抽单张，同类卡堆叠 |
| 预览、松手提交、非法落点回原位 | 高 | 预览与提交用同一规划器，拖动过程不修改已提交数据 |
| 牌堆排序 | 低 | 按 Rank 稳定升序，同 Rank 保持原有相对顺序 |
| 打乱牌序、新牌弹出 | 中 | Fisher-Yates 洗牌，生成新牌时自动找合法空位 |
| 桌面整理、附近兼容牌自动合堆 | 中高 | 有限桌面，有容量上限，整体失败时保留原布局 |
| 非玩家操作产生的重叠 | 高 | 统一 ResolveOverlaps 命令，同类且容量允许时合堆，否则找最近合法位置 |
| 拖动与飞行互斥 | 高 | 动画期间拒绝新拖动，取消/失焦清理会话，动画结束不触发领域改动 |
| 存档恢复 | 中高 | 保存卡牌属性、翻面、牌堆顺序和位置，版本与完整性验证，备份恢复 |

## 明确的首版方向

二维固定桌面，底层只负责卡牌对象与交互。先交付能直接打开的占位符演示场景，保留用户的 SampleScene。鼠标正常拖动移动整堆，Shift 拖动抽取一张。相同 Family 兼容，牌堆容量、桌面尺寸和几何参数集中配置。以上是本轮为推进开发作出的默认决策。

首版不包含战斗、配方、剧情、经济、联机、多指触控、无限桌面、任意旋转与异形卡片、规则脚本语言、玩家历史撤销。这里的“回滚”指失败交互的事务恢复。

## 状态与表现

CardData 保存唯一实例 ID、定义 ID、标签、兼容组、排序值、翻面与属性。PileData 保存位置与从底到顶的卡 ID。BoardSnapshot 提供可序列化快照，牌只能属于一个非空牌堆。

BoardEngine 是唯一状态写入口。命令在候选副本上完成规划与校验，成功后一次替换当前状态；拒绝时保留当前状态。拖拽只保留会话与预览，提交时重新使用相同规划规则。Unity 输入只产生操作，UI 插值到已提交结果。

## 算法取舍

不存在覆盖所有局面的“最好算法”。此处以可验证的正确性、局部交互延迟和有限规模下的维护成本为选择依据。

- 使用均匀空间哈希筛选附近牌堆，再做精确包围盒和距离判断。正常稀疏布局只访问邻近格，极端集中时退化为扫描候选。
- 排序使用稳定 O(n log n) 比较排序，保证同值卡片顺序可预测。
- 洗牌使用 Fisher-Yates，从剩余下标中等概率抽取，O(n) 时间，不用随机比较器排序。
- 牌堆成员用唯一 ID 和索引查询，避免通过场景对象寻找归属。
- 重叠处理与最近空位搜索都设置有限候选。“最近”指已枚举候选中距离最小的合法位置，不保证连续平面上的全局最近。仅接受已经验证的合法位置，搜索耗尽时明确失败，不无限迭代或删除卡片。
- 桌面整理使用可解释的确定性合堆与按实际包围盒排布。首版不求二维装箱的全局最优利用率。
- 一次命令可以进行 O(N) 快照复制与完整性校验，以交换明确的失败回滚边界。拖动开始时构建去除移动卡牌后的空间索引，后续预览复用并只查邻近候选，不逐帧复制全桌。性能用实际 100/500/1000 张卡压力结果衡量。
- 保存使用临时文件、完整性校验与同目录原子替换，读取先校验再恢复。异常文件不覆盖当前桌面。

## 范围上限与失败行为

默认桌面 1600×900，卡片 100×140，向上错开 22，单堆最多 20 张，全局最多 1000 张。数量上限和几何边界同时适用，1000 张上限不代表每种排列都能放入默认桌面。长牌堆放不下、桌面已满、容量不足、拖动期间收到冲突命令时返回明确结果。

保存版本首版为 1，不自动猜测未来版本结构。无效 ID、重复成员、越界、无穷数和损坏数据都拒绝恢复。Unity 不承担多线程并发访问，主线程连续输入通过会话状态串行化。

## 美术边界

预留卡面、卡框、桌面、图标、音效、音乐目录以及主题 ScriptableObject。所有资源可为空，此时使用程序占位符。文字由 Unity 排版，卡面插画不承载必须读取的规则文字。翻面、置顶、拖放、整理采用程序过渡动画。

## 验收

1. 演示场景可以直接运行，控件和快捷键可发现。
2. 拖牌、抽牌、堆叠、排序、弹牌、整理、翻面及预览都有实际入口。
3. 取消与非法落点不改变卡片集合和归属，连续输入没有重复提交。
4. 随机操作序列始终满足唯一 ID、唯一归属、容量与几何约束。
5. 存档往返保留位置、属性、牌堆顺序；损坏主存档可以恢复有效备份。
6. 实测算法，报告规模、耗时与尚未覆盖的性能范围。用户已明确接手 Unity 编译与运行检查。
7. README 简记本轮交付，MEMORY.md 保存实际入口和下一步锚点。
