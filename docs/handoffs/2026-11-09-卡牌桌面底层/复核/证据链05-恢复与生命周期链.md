## 1. 证据概览与调用拓扑 (Topology & Lifecycle)

生命周期与状态恢复链是保证桌面单机卡牌在遭遇玩家异常操作（切出窗口、按空格暂停、中途读档、场景重开）时不崩溃、不漏牌、不丢状态的核心支撑：

```
[玩家操作/系统事件]
   ├── 指针取消事件 ──────→ InputMgrComponent::OnPointerCanceled (0x1805DC610)
   │                           └── 转调 OnPointerUp (0x1805DD2F0) ──→ 触发 OnEndDrag / OnDrop 收尾
   ├── 空格/暂停按钮 ──────→ TaskGamePauseSpace / DialogParams::PauseGame ──→ 冻结逻辑时钟
   ├── 实体隐藏/退场 ──────→ BaseEntityLogic::OnHide ──→ CancellationTokenSource 取消 + 状态清洗
   ├── 游戏存档 ──────────→ BaseEntityLogic::SerializeRecordData ──→ 记录坐标/状态/ChildCardId
   └── 游戏读档 ──────────→ 阶段1: 实例化所有实体 (DeserializeRecordData)
                           阶段2: 拓扑缝合 (FixRecordData) ──→ GetEntity(ChildId) ──→ SetChild
```

### 核心方法拓扑表

| 虚地址 (VA) | 方法符号 | 证据等级 | 核心职责 |
| :--- | :--- | :--- | :--- |
| `0x1805DC610` | `InputMgrComponent::OnPointerCanceled` | **E1** | 指针取消事件入口：直接转调 `OnPointerUp` (VA `0x1805DD2F0`) 触发标准释放收尾（注：旧版误写为右键入口 0x1805DCFE0，已修正） |
| `0x1805DD2F0` | `InputMgrComponent::OnPointerUp` | **E1** | 指针抬起：检查 `isDragging`，依次调用 `OnEndDrag` 与 `OnDrop` 清空持有对象 |
| `0x1807066A0` | `BaseEntityLogic::OnHide` | **E1** | 实体退场/入池回收：触发取消令牌，解绑事件，清洗粒子与父子关系 |
| `0x180702BC0` | `BaseEntityLogic::GetCancellationTokenOnHide` | **E1** | 为所有挂起的飞行、跳跃、倒计时提供 UniTask/Async 销毁取消令牌 |
| `0x18070A540` | `BaseEntityLogic::SerializeRecordData` | **E1** | **存档序列化**：保存位置坐标、状态标志码，并将 `ChildCardId` 写入 `+0x98` |
| `0x180701B90` | `BaseEntityLogic::DeserializeRecordData` | **E1** | **读档阶段1**：反序列化卡牌实体基础属性并设置初始坐标 |

## 2. 核心反汇编逐项实证 (E1 Evidence)

### 2.1 读档两阶段缝合机制 (`SerializeRecordData` & `FixRecordData`)

原游戏对卡牌堆叠拓扑的持久化与恢复采用了极为经典的**两阶段重构（Two-Pass Reconstruction）**模式：

#### 阶段 A：序列化子节点 ID (`SerializeRecordData`, VA: `0x18070A540`)
```x86asm
; 写入当前坐标 (Vector3)
000000018070A580: movsd xmm0, mmword ptr [rbx+10Ch]   ; 读出卡牌坐标 (x, y)
000000018070A588: movsd mmword ptr [rcx+38h], xmm0    ; 写入存档记录偏移 +0x38 (x, y)
000000018070A58D: mov   dword ptr [rcx+40h], eax      ; z

; 写入状态标志码
000000018070A631: mov   eax, dword ptr [rbx+22Ch]     ; m_StateFlags
000000018070A637: mov   dword ptr [rcx+80h], eax

; 关键：获取子节点实体的全局 ID 并写入偏移 +0x98
000000018070A6C7: mov   rcx, qword ptr [rbx+1B8h]     ; rcx = this.m_Child
000000018070A6CE: test  rcx, rcx                      ; m_Child != null ?
000000018070A6D1: je    WRITE_ZERO
000000018070A6D5: call  EntityLogicWithData::get_Id   ; 获取子卡牌 ID
WRITE_ZERO:
000000018070A6DF: mov   dword ptr [rdi+98h], eax      ; RecordCardData.ChildCardId = eax
```

#### 阶段 B：读档后拓扑原子缝合 (`FixRecordData`, VA: `0x180702120`)
在所有卡牌根据存档实例化完毕后，系统对全场实体执行 `FixRecordData`：
```x86asm
; 1. 检查是否存在子节点
0000000180702151: cmp   dword ptr [rax+98h], 0        ; ChildCardId != 0 ?
0000000180702158: je    RETURN                        ; 无子卡牌，直接返回

; 2. 根据 ChildCardId 在实体管理器中查找已实例化的卡牌对象
00000001807021A3: mov   edx, dword ptr [rax+98h]      ; edx = ChildCardId
00000001807021A9: call  EntityComponent::GetEntity    ; rax = childEntity

; 3. 尾调用 SetChild 建立双向互反引用
00000001807021B1: mov   rdx, rax                      ; rdx = childEntity
00000001807021B4: mov   rcx, rbx                      ; rcx = this
00000001807021BC: jmp   BaseEntityLogic::SetChild     ; this.m_Child = child, child.m_Parent = this
```

**实证结论**：
1. 存档无需存储复杂的树形嵌套 JSON，只需在平铺的卡牌数据中记录 `ChildCardId`；
2. 读档时，`FixRecordData` 遍历调用 `SetChild`，一次性瞬时恢复了全桌所有多叠卡牌的父子链表关系。

### 2.2 指针取消与释放路由 (`OnPointerCanceled`, VA: `0x1805DC610`)

反汇编指令证实，原游戏并未设计单独的回弹协议，而是**将指针取消事件直接转调为标准指针抬起处理**：
```x86asm
; 0x1805DC610: InputMgrComponent::OnPointerCanceled
00000001805DC68D: call 000000018209CCB0
00000001805DC692: movups xmm0, xmmword ptr [rbp]     ; 读取指针事件数据
00000001805DC699: lea    rdx, [rsp+20h]
00000001805DC69E: mov    rcx, rbx                     ; this (InputMgrComponent)
00000001805DC6A1: movaps xmmword ptr [rsp+20h], xmm0
00000001805DC6A6: call   00000001805DD2F0             ; 直接转调 InputMgrComponent::OnPointerUp!
00000001805DC6BF: ret
```

**原版事实与证据边界**：
1. `OnPointerCanceled` 接收到系统取消中断后，直接调用 `OnPointerUp`（VA `0x1805DD2F0`）。
2. `OnPointerUp` 随后读取 `[rdi+0x80]`（`isDragging`），如果处于拖动状态，依次派发 `OnEndDrag`（槽6）与 `OnDrop`（槽7），走既有的落点吸附与回滚逻辑。
3. **边界与限制澄清**：
   - 此机制证实了原版存在“取消即抬起”的保护路由。
   - 但 Unity Input System 的 `canceled` 回调在 Windows 平台窗口失焦（Alt+Tab）或鼠标跨越视口边界时是否 100% 触发，取决于输入映射与设备焦点消息；原版并未在底层设立独立的失焦看门狗轮询，因此不能作“在所有异常切屏下绝对不卡死”的无条件承诺，必须结合真实运行时平台事件验证。

### 2.3 实体回收与状态清洗机制 (`OnHide`, VA: `0x1807066A0`)

卡牌被消耗、合成或退场入池时，`OnHide` 严格执行六步清洗：
1. **生命周期取消信号**：在实体销毁或隐藏时触发取消源，但原游戏中具体哪些异步任务（如飞牌插值、展开计时）实际监听了该 Token 尚未逐一闭合消费链路；工程落地需主动显式取消；
2. **事件解绑**：调用 `EventComponent.Unsubscribe` 注销全部注册的拖拽/选择广播监听；
3. **特效与高亮清空**：注销粒子系统与材质高亮；
4. **断开父子关联**：调用 `ResetParentChild` 将 `m_Parent` 与 `m_Child` 置空，防止对象池中的旧卡牌残留对外部实体的野指针；
5. **物理状态复位**：重置刚体速度、碰撞层与 `m_IsDrag=0` 标志；
6. **归还对象池**：重置为初始状态，等待下一次 `OnShow` 复用。
（注：回收清洗覆盖已纳入该流程的实体状态，但在全局管理器中尚未闭环所有异步任务的外部引用链，不能推论为整个进程的零内存泄露或绝对零残留。）

## 3. 本项目工程落地规范 (Design & Migration: D)

在本项目 `Assets/IslandSurvival` 或独立牌桌中，状态恢复必须对齐以下协议：

### 3.1 存档数据模型
```csharp
[System.Serializable]
public class SavedDeskCardDTO
{
    public string CardId;
    public string DefinitionId;
    public float PosX, PosY, PosZ;
    public int StateFlags;
    
    // 拓扑指针仅存 ChildCardId
    public string ChildCardId; 
}
```

### 3.2 读档两阶段执行协议
```csharp
public void LoadGame(SavedGameDTO save)
{
    // Pass 1: 批量实例化所有卡牌，建立 ID 索引表
    var entityMap = new Dictionary<string, DeskCardView>();
    foreach (var cardDto in save.Cards)
    {
        var view = SpawnCard(cardDto);
        entityMap[cardDto.CardId] = view;
    }

    // Pass 2: 拓扑缝合 (对齐原游戏 FixRecordData)
    foreach (var cardDto in save.Cards)
    {
        if (!string.IsNullOrEmpty(cardDto.ChildCardId) && entityMap.TryGetValue(cardDto.ChildCardId, out var childView))
        {
            var parentView = entityMap[cardDto.CardId];
            parentView.SetChild(childView); // 内部同时设置 childView.Parent = parentView
        }
    }
}
```

### 3.3 失焦保护与对象池零残留
1. **失焦保护**：在 `Update` / `OnApplicationFocus(false)` 中监测拖拽状态，遇中断立即触发 `AbortDrag()` 回弹。
2. **对象池清洗**：卡牌 `Recycle` 时，强制执行 `DeregisterEvents()`, `KillActiveTweens()`, `ResetParentChild()`，确保复用卡牌干净如初。
