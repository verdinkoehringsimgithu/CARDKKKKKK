## 1. 证据概览与调用拓扑 (Call Topology)

牌堆（Stack）在原游戏中并未采用独立的“容器类”（如 `List<Card>` 或单独的 `PileEntity`），而是采用纯正的**侵入式双向链表（Intrusive Doubly-Linked List）拓扑结构**，直接由 `BaseEntityLogic` 的 `m_Parent` 与 `m_Child` 字段串联构成整叠牌。

```
                         [桌面卡牌 A (Root)]
                            m_Parent = null
                            m_Child = B
                                ↓
                         [桌面卡牌 B (Middle)]
                            m_Parent = A
                            m_Child = C
                                ↓
                         [桌面卡牌 C (Leaf/Top)]
                            m_Parent = B
                            m_Child = null
```

## 2. 核心反汇编逐项实证 (E1 Evidence)

### 2.1 堆叠兼容与上限校验 (`CanHaveCardOnTop`, VA: `0x180700BC0`)

反汇编指令表明，原游戏卡牌堆叠必须严格通过四道门禁：

```x86asm
; 门禁 1：状态位校验 (不可处于动画、飞行、锁定等非法状态)
0000000180700BCA: test dword ptr [rcx+22Ch], 1E2h
0000000180700BDA: ja   REJECT
0000000180700BE0: cmp  dword ptr [rcx+180h], 0
0000000180700BE7: jne  REJECT

; 门禁 2：OverlapTypeId 必须一致且非 0
0000000180700C0A: mov  rax, qword ptr [rcx+128h]       ; rax = this.m_CardData
0000000180700C1A: cmp  dword ptr [rax+68h], 0          ; OverlapTypeId == 0 ?
0000000180700C1E: je   REJECT
0000000180700C2D: mov  rdx, qword ptr [rdx+128h]       ; rdx = other.m_CardData
0000000180700C3D: mov  ecx, dword ptr [rax+68h]
0000000180700C40: cmp  dword ptr [rdx+68h], ecx         ; this.OverlapTypeId == other.OverlapTypeId ?
0000000180700C43: jne  REJECT

; 门禁 3：牌堆总层数不得超过 TbBaseConfig.EntityTopNum
0000000180700C4B: mov  rcx, rdi                        ; this
0000000180700C4E: call BaseEntityLogic::GetTopNum      ; 计算 this 当前所在整堆卡牌总数 (遍历父+子链)
0000000180700C58: mov  ebx, eax
0000000180700C5A: call BaseEntityLogic::GetTopNum      ; 计算 other 当前所在整堆卡牌总数 (遍历父+子链)
0000000180700C66: lea  esi, [rbx+rax]                  ; 合并总数 = countA + countB
0000000180700C74: call TbBaseConfig::get_EntityTopNum  ; 读取真实配置堆叠上限
0000000180700C79: cmp  esi, eax
0000000180700C7B: jg   REJECT                          ; 超过配置上限拒绝堆叠

; 门禁 4：达到20张触发隐藏成就/任务 (注意：20张是任务触发门槛，非通用堆叠上限)
0000000180700C7D: cmp  esi, 14h                        ; 20 张 (0x14)
0000000180700C80: jl   ACCEPT

0000000180700CCD: call GameData::AddTaskIdNum
```

#### 原生 `GetTopNum` 双向遍历算法实证 (VA: `0x1807044C0`, E1)
原生指令证实，卡牌堆叠数量统计绝非仅向上查找父节点，而是**同时遍历父链与子链**以获得整堆的真实全量深度：
```x86asm
00000001807044EE: mov  rdi, qword ptr [rsi+1B0h]       ; rdi = this.m_Parent
00000001807044F5: mov  ebx, 1                          ; 初始计数 = 1 (计入自身)

; 循环 1：沿 +0x1B0 向上累加所有父级节点 (0x180704500 ~ 0x180704534)
000000018070451A: mov  rcx, rdi
000000018070451D: call UnityEngine.Object::op_Implicit
0000000180704522: test al, al
0000000180704524: je   0000000180704536                 ; 父链到达根部，进入子链统计
0000000180704526: inc  ebx                              ; 计数累加 +1
000000018070452D: mov  rdi, qword ptr [rdi+1B0h]       ; rdi = rdi.m_Parent
0000000180704534: jmp  0000000180704500

; 循环 2：沿 +0x1B8 向下累加所有子级节点 (0x180704536 ~ 0x180704574)
0000000180704536: mov  rdi, qword ptr [rsi+1B8h]       ; rdi = this.m_Child
000000018070455A: mov  rcx, rdi
000000018070455D: call UnityEngine.Object::op_Implicit
0000000180704562: test al, al
0000000180704564: je   0000000180704576                 ; 子链到达叶子节点，统计完毕
0000000180704566: inc  ebx                              ; 计数累加 +1
000000018070456D: mov  rdi, qword ptr [rdi+1B8h]       ; rdi = rdi.m_Child
0000000180704574: jmp  0000000180704540

0000000180704576: mov  rsi, qword ptr [rsp+38h]
000000018070457B: mov  eax, ebx                        ; 返回整叠卡牌完整总数
0000000180704587: ret
```

**关键结论**：
1. 堆叠判定基于 `CardData.OverlapTypeId` (`+0x68`)。不同类型的卡牌（即使都是资源或道具）只要 `OverlapTypeId` 不相等或为 0，就坚决不可堆叠。
2. 堆叠深度通过同时遍历父子双向链表的 `GetTopNum` 获得完整堆总张数。若仅沿 Parent 统计，在拖动中段或底部卡牌堆叠时会严重漏算子牌，导致错误放行超限牌堆。
3. 准入上限严格来自配置表 `TbBaseConfig.get_EntityTopNum`（VA `0x1806D2F70` 读取 `+0x660`）。经从 `baseconf_tbbaseconfig.bytes`（偏移 `0xd92`）二进制实证提取，**原游戏配置的堆叠上限精确为 30 张 (`EntityTopNum = 30`)**；反汇编中的 `esi >= 0x14`（20张）是触发隐藏成就/任务 `TaskCardOnTop` 的专用业务门槛，绝非牌堆物理上限。
4. 原表配套层叠物理参数（E1实证）：
   - `EntityOverlayOffset = -0.22f`：卡牌正常展开堆叠时沿 Y 轴的向下偏移量；
   - `EntityCollapsedOverlayOffset = -0.06f`：卡牌折叠紧凑堆叠时沿 Y 轴的向下偏移量；
   - `EntityOverlayHeightOffset = 0.001f`：每层堆叠卡牌在 Z 轴的微小抬升量，用于消除 Z-fighting 渲染穿插；
   - `EntityHeight = 0.1f`，`EntityBoxHeight = 0.065f`，`EntityFlyHeight = 0.164f`。

### 2.2 松手堆叠目标搜索与防环机制 (`CheckIfCanAddOnStack`, VA: `0x180700E00`)

当玩家松开拖拽的卡牌时，系统在落点区域枚举候选碰撞体，并通过严格算法锁定最适宜的叶子节点：

```x86asm
; 循环遍历所有碰撞候选对象
0000000180700EE7: lea  rcx, [rsp+48h]                  ; candidateEnumerator
0000000180700EEC: call MoveNext
0000000180700EF1: test al, al
0000000180700EF3: je   LOOP_END

; 步进 1：沿 m_Child 链一路向上寻找最顶端卡牌 (Top Leaf)
0000000180700F2F: mov  rsi, qword ptr [rdi+1B8h]       ; rsi = candidate.m_Child
0000000180700F53: call op_Inequality(rsi, null)
0000000180700F58: test al, al
0000000180700F5A: je   LEAF_FOUND
0000000180700F5C: mov  rdi, qword ptr [rdi+1B8h]       ; rdi = rdi.m_Child
0000000180700F63: jmp  0000000180700F26

; 步进 2：防环校验与自引用防御
LEAF_FOUND:
0000000180700F80: mov  rcx, rdi
0000000180700F83: call op_Equality(candidateTop, this) ; 不能挂接自己
0000000180700F88: test al, al
0000000180700F8A: jne  NEXT_CANDIDATE
0000000180700F96: mov  rcx, rdi
0000000180700F99: call BaseEntityLogic::IsChildOf       ; candidateTop 不能是 this 的子孙 (防止成环!)
0000000180700F9E: test al, al
0000000180700FA0: jne  NEXT_CANDIDATE

; 步进 3：调用 CanHaveCardOnTop 校验规则
0000000180700FAF: call BaseEntityLogic::CanHaveCardOnTop
0000000180700FB4: test al, al
0000000180700FB6: je   NEXT_CANDIDATE

; 步进 4：计算 2D 平面距离，挑选距离最近的候选卡
000000018070104D: call Vector3::Distance
0000000180701052: comiss xmm6, xmm0                     ; 与已有最小值比较
0000000180701055: jbe  NEXT_CANDIDATE
000000018070105B: mov  r12, rdi                        ; 记录最佳候选 top card
0000000180701066: movaps xmm6, xmm0                    ; 更新最小距离
```

循环结束后，若找到最佳目标 `r12`，执行原子挂接：
```x86asm
00000001807010D9: mov  rcx, r15                        ; this
00000001807010DC: call BaseEntityLogic::SetParent(null) ; 先解除原父级关系
00000001807010E4: mov  rdx, r12                        ; target top card
00000001807010E7: mov  rcx, r15                        ; this
00000001807010EA: call BaseEntityLogic::SetParent(r12)  ; 挂接到目标卡上方
00000001807010EF: mov  al, 1
0000000180701110: ret
```

### 2.3 抓取子树的拓扑分割 (`OnBeginDrag` & `SetDrag`)

在桌面上拖拽卡牌时，存在两种截然不同的物理行为：
1. **拖底牌**：整叠牌一起移动。
2. **拖中段牌**：从中段抽取，中段牌与它上方的所有牌作为一个整体被带走，而中段牌下方的牌留在桌面上原位不动。

反汇编揭示了其优雅的实现逻辑：
```x86asm
; 07268-BaseEntityLogic-OnBeginDrag (VA: 0x180704DE0)
; 判断自身来源 sil: 0 为普通桌面拖动
0000000180704FC2: test sil, sil
0000000180704FC5: jne  FROM_FACILITY
0000000180704FC7: xor  r8d, r8d
0000000180704FCA: call BaseEntityLogic::SetParent(null) ; 断开与下方父节点的关联！

; 保留自身的 m_Child 链，并对其递归置位拖动状态
000000018070519E: mov  rcx, qword ptr [rbx+1B8h]        ; rcx = this.m_Child
00000001807051A5: test rcx, rcx                         ; 是否有子卡牌
00000001807051A8: je   0000000180705418                 ; 无子卡牌直接跳出
00000001807051AE: xor  r8d, r8d
00000001807051B1: mov  dl, 1                            ; isDrag = true
00000001807051B3: call BaseEntityLogic::SetDrag         ; 级联设置所有子卡牌拖动中
```

而在 `SetDrag` (`VA: 0x18070AA20`) 中：
- 循环遍历 `m_Child` 链表。
- 将每个子节点的 `m_IsDrag` 置为 true。
- 调用 `SortingLayerOrderControl::SetSortingLayerName` 将整串卡牌一并提升到顶层拖拽排序层。

### 2.4 移入设施时的原子切分 (`RemoveParentChild`, VA: `0x180709F80`)

在已分析的 `BaseFormEntityLogic::AddBaseCardSlotEntity` (VA: `0x1804F1AA0`) 入槽路径中，卡牌入槽前调用了 `RemoveParentChild` 将当前所持卡牌单独摘除；其余卡牌前后缝合留在桌面上。其他设施或界面是否具备其他批量接收逻辑，仍需作为待查项保持边界。

```x86asm
; 07280 紧邻区域：BaseEntityLogic::RemoveParentChild (VA: 0x180709F80)
0000000180709FB0: mov  rdi, qword ptr [rbx+1B0h]       ; rdi = this.m_Parent
0000000180709FD2: test al, al                          ; m_Parent != null ?
0000000180709FD4: je   CHECK_CHILD
0000000180709FE6: mov  rdx, qword ptr [rbx+1B8h]       ; rdx = this.m_Child
0000000180709FED: mov  qword ptr [rcx+1B8h], rdx       ; m_Parent.m_Child = this.m_Child (前向缝合!)

CHECK_CHILD:
000000018070A007: mov  rdi, qword ptr [rbx+1B8h]       ; rdi = this.m_Child
000000018070A029: test al, al                          ; m_Child != null ?
000000018070A02B: je   CLEAN_SELF
000000018070A039: mov  rdx, qword ptr [rbx+1B0h]       ; rdx = this.m_Parent
000000018070A040: mov  qword ptr [rcx+1B0h], rdx       ; m_Child.m_Parent = this.m_Parent (后向缝合!)

CLEAN_SELF:
000000018070A05E: mov  qword ptr [rbx+1B0h], rdi        ; this.m_Parent = null (rdi已置0)
000000018070A071: mov  qword ptr [rbx+1B8h], rdi        ; this.m_Child = null
000000018070A084: jmp  00000001803F2310                 ; 尾调用写屏障/返回
```

**实证价值**：
1. 原作对牌堆切分采用了标准的**双向链表结点摘除（Unlink）算法**。
2. 无论该牌处于栈顶、栈底还是栈中，一旦入槽，原堆叠链表自动将它的前驱与后继节点缝合为新的一条连续堆叠；而入槽卡牌的父子引用全部清零，孤身进入槽位。
3. 未入槽的余下卡牌完全不受影响，保留在桌面或原位置。

## 3. 本项目工程落地规范 (Design & Migration: D)

在本项目 `Assets/IslandSurvival` 或独立牌桌底层中，此前存在将一叠牌当作单一整体或平面数组处理的模糊地带，导致出现“整组被拖入槽位”或“拆分后状态断裂”的隐患。依照反汇编证据链，确立以下实现规范：

### 3.1 数据模型统一
```csharp
public class DeskCardEntity
{
    public string CardId;
    public int OverlapTypeId; // 映射自 CardData.OverlapTypeId
    
    // 侵入式双向链表指针
    public DeskCardEntity ParentCard; // 下方的卡牌
    public DeskCardEntity ChildCard;  // 上方的卡牌
    
    public bool IsRoot => ParentCard == null;
    public bool IsLeaf => ChildCard == null;
    
    /// <summary>
    /// 对齐原生 BaseEntityLogic::GetTopNum (VA 0x1807044C0)：
    /// 同时向上遍历 Parent 链与向下遍历 Child 链，统计整叠卡牌完整总张数。
    /// 严禁仅数 Parent 链，否则拖拽非叶子节点堆叠时会漏算子牌造成超限放行！
    /// </summary>
    public int GetFullStackCount()
    {
        int count = 1;
        var p = ParentCard;
        while (p != null)
        {
            count++;
            p = p.ParentCard;
        }
        var c = ChildCard;
        while (c != null)
        {
            count++;
            c = c.ChildCard;
        }
        return count;
    }
}
```

### 3.2 规则校验门禁
1. **类型匹配**：`OverlapTypeId != 0 && source.OverlapTypeId == target.OverlapTypeId`。
2. **总高限制**：`source.GetFullStackCount() + target.GetFullStackCount() <= config.EntityTopNum`。
   - 注意：准入上限受配置表 `EntityTopNum` 约束；20 张（`0x14`）为成就/任务触发门槛，非通用硬编码上限。
3. **环检测与防自引用**：在拖拽松手时，严禁将卡牌放置在其子树中的任何卡牌上 (`IsChildOf` 保护)。

### 3.3 交互与槽位切分
1. **拖拽拾起**：
   - 拾起非根节点卡牌时，先触发 `ParentCard.ChildCard = null; ParentCard = null;`。
   - 保留自身 `ChildCard` 链表，整组子树跟随鼠标移动。
2. **槽位吸附**：
   - 拖拽卡牌组进入工作台槽位时，**严禁整组吸附**。
   - 调用原子摘除 `RemoveParentChild()`，仅将当前所持卡牌入槽。
   - 携带的子树卡牌平稳掉落回桌面上并重新成为独立的顶端卡牌。
