## 1. 证据概览与运动体系结构 (Motion Architecture)

原游戏在表现层构建了清晰且高度特化的运动流水线，分为四层：
1. **动画剪辑层（AnimationClip）**：窗口展开与折叠（0.25s / 0.3333s 动画曲线；ProduceFromIdle/FieldFormIdle 为空绑定占位，WorkFormIdle 维持 10 绑定静态姿态）；
2. **插值与弹道辅助层（TransformHelper）**：二阶德卡斯特里奥贝塞尔曲线（Quadratic Bezier）、抛物线跳跃（JumpTowards）、定向飞行（FlyPosition）、抓取晃动（RotWobble/RotateShake）；
3. **实体控制层（CardBehaviourControl）**：为卡牌实体配置运动参数并桥接驱动 TransformHelper；
4. **桌面物理避让层（BaseEntityLogic::PushAwayFromOthers / UpdatePhysics）**：松手后基于 2D 重叠向量计算斥力冲量，沿堆叠根节点执行物理排斥推开（本项目工程落地采用有限步松弛保证无死循环）。

## 2. 核心数学与反汇编逐项实证 (E1 Evidence)

### 2.1 抛物线贝塞尔弹道公式 (`CalculateBezierPoint`, VA: `0x18066A640`)

产物从设施弹飞至桌面以及卡牌吸附入槽时，均采用标准二阶德卡斯特里奥（de Casteljau）贝塞尔算法：

```x86asm
000000018066A65A: movss   xmm9, dword ptr [00000001826F9B8Ch] ; 常量 1.0f
000000018066A663: movaps  xmmword ptr [rsp+10h], xmm10
000000018066A669: movaps  xmm3, xmm9                          ; xmm3 = 1.0f
000000018066A66D: movss   xmm10, dword ptr [rsp+90h]          ; xmm10 = t
000000018066A677: subss   xmm3, xmm10                         ; xmm3 = (1.0f - t)

; 计算第 1 段插值：P01 = (1-t)*P0 + t*P1
movsd   xmm0, mmword ptr [rdx]            ; P0.xy
mulss   xmm0, xmm3                        ; (1-t) * P0.x
mulss   xmm8, xmm10                       ; t * P1.x
addss   xmm8, xmm0                        ; xmm8 = P01.x

; 计算第 2 段插值：P12 = (1-t)*P1 + t*P2
movsd   xmm5, mmword ptr [r9]             ; P2.xy
mulss   xmm0, xmm3                        ; (1-t) * P1.x
mulss   xmm5, xmm10                       ; t * P2.x
addss   xmm5, xmm0                        ; xmm5 = P12.x

; 计算终段贝塞尔插值：B(t) = (1-t)*P01 + t*P12
subss   xmm9, xmm10                       ; (1-t)
mulss   xmm8, xmm9                        ; (1-t) * P01.x
mulss   xmm5, xmm10                       ; t * P12.x
addss   xmm8, xmm5                        ; B(t).x = (1-t)^2 P0.x + 2t(1-t) P1.x + t^2 P2.x
```

**数学实证**：
- 输入三点：起始点 $P_0$、控制拱高点 $P_1$（由产物飞出源或卡槽高度偏移动态生成）、落点 $P_2$。
- 原生指令完全展开了标准二次贝塞尔方程，无外部黑盒依赖。

### 2.2 物理避让与有限步推开 (`PushAwayFromOthers`, VA: `0x180709900`)

卡牌松手落在已有卡牌密集区域时，既不会穿透重叠，也不会无限抖动。反汇编完整揭示了其推开算法：

```x86asm
; 1. 寻根至底牌 (Root Card)
00000001807099B8: mov  rbx, qword ptr [rax+1B0h]       ; rbx = this.m_Parent
00000001807099D2: mov  rcx, rbx
00000001807099D5: call op_Inequality(rcx, null)
00000001807099E5: je   ROOT_FOUND
00000001807099E7: mov  rdi, qword ptr [rdi+1B0h]       ; rdi = rdi.m_Parent
00000001807099FA: jmp  00000001807099B1

ROOT_FOUND:
; 2. 状态锁校验 (已锁定的实体不产生物理避让)
00000001807099FC: cmp  byte ptr [rdi+208h], 0          ; isLocked ?
0000000180709A03: jne  EXIT

; 3. OverlapBox 区域碰撞检测
0000000180709AB0: call Physics::OverlapBoxNonAlloc
0000000180709AB5: test eax, eax                        ; 命中卡牌数 > 0 ?
0000000180709AB7: jle  EXIT

; 4. 遍历并排除无效对象
0000000180709B6C: call  UnityEngine.Object::op_Equality ; 排除自己 (返回布尔结果入 al)
0000000180709B71: test  al, al                          ; 检查自身相等性
0000000180709B73: jne   NEXT                            ; 是自身则跳过
0000000180709B7E: cmp   byte ptr [rbx+167h], al         ; 排除正在被拖动的卡牌 (此时 al 为 0，即比较 m_IsDrag != 0)
0000000180709B84: jne   NEXT
0000000180709BBE: call  BaseEntityLogic::IsChildOf      ; 排除同一堆叠中的子树卡牌
0000000180709BC3: test  al, al                          ; 若是同一子树则跳过
0000000180709BC5: je    0000000180709C12                ; 否则继续计算推开斥力

; 5. 计算 2D 平面斥力向量与推开位移
0000000180709CB6: movss xmm0, dword ptr [rsp+40h]      ; posA.x
0000000180709CBC: subss xmm0, xmm1                     ; dx = posA.x - posB.x
0000000180709CC8: movd  xmm1, ebx                      ; posA.z
0000000180709CCC: subss xmm1, dword ptr [rax+8]        ; dz = posA.z - posB.z
0000000180709CFD: call  Vector2::Normalize             ; 归一化推开方向
0000000180709D1A: divss xmm9, xmm1                     ; 计算重叠率 overlap / dist
0000000180709D1F: subss xmm8, xmm9                     ; 斥力衰减 impulse = 1.0f - ratio
0000000180709D2D: call  BaseEntityLogic::GetForceNum   ; VA 0x1807035A0: 读取推力放大系数 -> xmm0
0000000180709D32: movaps xmm6, xmm0                    ; xmm6 = forceNum
; 随后 0x180709D3F ~ 0x180709DBB 结合 forceNum 与斥力向量计算最终目标坐标并写入 Transform (m_TargetPos +0x1C0)
```

**关键机制实证**：
1. **整堆以根节点为准**：无论松手拖动的是单卡还是多张牌，碰撞与推开以最底部的 `Root` 实体为基准计算，杜绝叠牌内部被撕裂。
2. **拖拽卡排他性**：正在拖拽中的卡牌 (`m_IsDrag=1`) 享有绝对物理特权，不被周围静止牌推开。
3. **同堆排他性**：`IsChildOf` 严格过滤同一牌堆的所有父子卡牌，牌堆内部不会互相推开造成抖动。

### 2.3 抓取晃动动效参数打包 (`RotWobble`, VA: `0x18066ADE0`)

玩家拾起卡牌时，卡牌产生晃动动效。反汇编（VA: `0x18066ADE0`）证实其将 4 个浮点参数打包传递至内部动画插值调度器（`0x180A645D0`）：
- `[rsp+38h]`: 传入浮点参数 1（推测对应角度幅度 Amplitude）
- `[rsp+3Ch]`: 传入浮点参数 2（推测对应频率/速度 Frequency）
- `[rsp+40h]`: 传入浮点参数 3（推测对应衰减系数 Damping）
- `[rsp+44h]`: 传入浮点参数 4（推测对应持续时长 Duration）

指令实证（E1）表明原游戏通过向插值引擎传入这 4 个浮点参数驱动动效；但具体内部衰减数学函数（是否为阻尼正弦）未在当前反汇编中闭环提取，列为表现层推论（E2）。

**实证结论与曲线通道解析 (E1)**：
- 场所窗口展开动画（`workformexpan01`）包含 15 个实质 `genericBindings` 与 25 个通道（`m_ValueArrayDelta` 端点 + `m_StreamedClip` 19 通道 Hermite 曲线 + `m_ConstantClip` 6 通道静态值），在 20 帧（0.3333s @ 60fps，$\Delta t = \frac{1}{3}\text{s}$）内按三次 Hermite 样条多项式 $f(t) = c_0 t^3 + c_1 t^2 + c_2 t + c_3$ 平滑完成视觉展开：
  1. **层级位移展开 (`Transform.m_LocalPosition`, TypeID 4, Attribute 1)**：
     - 通道 0（X 轴）：$c_0=-43.2, c_1=21.6, c_2=0.0, c_3=1.276$。初速 $f'(0)=0$，末速 $f'(1/3)=0$，X 坐标自 `1.276` 平滑缓动至 `2.076`（位移增幅 +0.8）；
     - 通道 3（X 轴）：$c_0=43.2, c_1=-21.6, c_2=0.0, c_3=1.276$。初速与末速均为 0，X 坐标自 `1.276` 对称移动至 `0.476`（位移 -0.8）；
  2. **缩放淡入 (`Transform.m_LocalScale`, TypeID 4, Attribute 3)**：
     - 通道 7（Y 轴缩放）：$c_0=-27.0, c_1=13.5, c_2=0.0, c_3=0.5$。在 $t \in [0, 1/3\text{s}]$ 内单调平滑由 `0.5` 缓动至 `1.0`，导数初值与末值均为 0（标准三次 SmoothStep/Ease-In-Out，无过冲振荡 overshoot，非弹性物理回弹）；
  3. **透明度淡入 (`SpriteRenderer.m_Color.a`, TypeID 212, Attribute 304273561)**：
     - 通道 10（Alpha 透明度）：$c_0=-54.0, c_1=27.0, c_2=0.0, c_3=0.0$。三次 Ease-In-Out 曲线，自 `0.0` 平滑过渡至 `1.0`（非直角折线或无缓动纯线性）；
  4. **子节点可见性激活 (`GameObject.m_IsActive`, TypeID 1, Attribute 2086281974)**：通道 11~18 控制各卡槽与边框对象的激活状态。
- `workformidle.anim` 包含 10 个绑定（8 项 `m_IsActive`，1 项 `m_LocalPosition`），时长 0 秒（1帧），作为展开完成后的静态姿态维持。
- `produceformidle.anim`（以及 `adverseformidle.anim`, `fieldformidle.anim`）时长虽为 1.0 秒（60帧），但其实际 `genericBindings` 数为 0，确证为空绑定占位剪辑；由于原包存在其他包含曲线的 idle/loop 剪辑（如环境风摆动画），不能以此特定剪辑的空绑定断言原游戏全局完全不存在呼吸微动。

## 3. 本项目工程落地规范 (Design & Migration: D)

在本项目 `Assets/IslandSurvival` 或独立牌桌中，动画与运动体系必须遵循以下标准：

### 3.1 弹道计算器统一实现
```csharp
public static class MotionCurves
{
    // 二阶抛物线贝塞尔曲线（与原游戏 TransformHelper::CalculateBezierPoint 0x18066A640 完全一致）
    public static Vector3 QuadraticBezier(Vector3 p0, Vector3 p1, Vector3 p2, float t)
    {
        float u = 1.0f - t;
        return (u * u * p0) + (2.0f * u * t * p1) + (t * t * p2);
    }

    // 默认拱高控制点生成器
    public static Vector3 CalculateArcControlPoint(Vector3 start, Vector3 target, float arcHeight = 1.5f)
    {
        Vector3 mid = (start + target) * 0.5f;
        mid.y += arcHeight; // 或 2D 桌面中的向上偏移
        return mid;
    }
}
```

### 3.2 物理推开松弛规范 (本项目工程设计: D)
1. **单一根节点判定**：执行碰撞检测前，遍历 `ParentCard` 直至 `Root`，以 `Root.Position` 作为碰撞核心。
2. **工程设计松弛迭代（D）**：原游戏依靠松手触发 PushAwayFromOthers 及每帧 UpdatePhysics/UpdatePosition 插值逐步收敛；在本项目纯逻辑或表现层中，建议将单次排斥松弛限制在 4~8 轮迭代内，防止极端密集时的计算抖动（此 4~8 轮属于本项目工程设计 D，非原游戏原生常量）。
3. **安全边界收束**：卡牌被推开时，位置受视口边界 `DeskBounds` 钳位保护，严禁被推至屏幕不可见区域。
