## 2. 本轮新增的直接证据

复核文件在同目录 `复核/`。定位以原生VA或资源pathID为准；注释仅辅助导航，不覆盖原始反汇编。

### 2.1 正确的本程序集方法映射

- PE ImageBase：`0x180000000`。
- `Assembly-CSharp.dll`模块结构候选文件偏移：`0x27e46b0`；名称指针指向PE中实际程序集名称字符串。
- 方法数量15545，方法指针表VA：`0x183103e00`。
- 以`MethodDef.Token & 0xFFFFFF`取得RID，索引模块表`RID-1`；15545个方法RID唯一且完整，非零指针位于可执行区。
- 对旧R02的40个记录逐一比较：40个不一致。详见`复核/原生方法地址独立核对.json`。
- 本轮64个关注方法记录中58个有实际反汇编输出。6个无可用异常表边界且不满足简短ret检查，明确未反汇编，不能标为已还原。
- 反汇编候选范围延伸至下一已知本程序集方法入口，可能含填充/未命名辅助函数；不是完整C#反编译。直接调用可定位，虚调用/接口调用与共享函数地址不唯一归因。

### 2.3 槽位和窗口运动的实物证据

- CardSlot：`assets/gamemain/entities/timer/cardslot.prefab`，根pathID `5125451118264684272`。
- 独立三维触发碰撞体，尺寸`0.64 × 0.852 × 0.1`，带选择对象、白/绿/红颜色列表、名称文字、slot与lock显示对象。不只是窗体里画出的装饰矩形。
- WorkFormExpan01～04：片段中起止时间`0～0.3333`秒，动画绑定分别15/20/24/30个。
- ExploreFormExpan01～03：`0～0.25`秒，绑定分别7/8/9个。Expan04没有绑定，不能只凭文件名当成有效展开运动。
- 这些片段的传统FloatCurves等数组为空，实际信息在编译后的MuscleClip/ClipBindingConstant，不能判断“原作没有动画”。完整曲线采样与绑定对象hash映射尚待解码。
- 本轮新增Map包解包，并重新直接提取21个有关对象/片段（含一个地图物件样本）；没有把整个Map包都冒充已分析。
- 新递归提取直接读TypeTree并检查外部fileID。旧手写布局解析器在Map的部分对象曾发生越界，不能无条件复用于所有包；新提取输出本轮21项未见_parse_error，仍未覆盖全资源。

## 3. 项目底层欠账：按操作链而非按界面列清单

| 操作/能力 | 项目现状 | 缺口和下一项取证 |
|---|---|---|
| 身体牌叠放、拆单牌、拖子堆 | VoyageCardState无堆ID/父子/顺序，拖动只持有一个CardId | 不是隐藏开关，是该模块未实现；补查SetParent/Child、OnBeginDrag条件、Compatibility配置与序列化 |
| 拿起后的整体拖动与层级 | 仅原牌跟鼠标，缺堆集合、提层还原和晃动统一会话 | 追OnBeginDrag/SetDrag/OnEndDrag及CardBehaviourControl；明确取消保留哪些状态 |
| 拖到资源点卡上 | FindDropTargetCard用IsAvailable过滤，当前场所已放在Staged时会被排除 | 自己的活动场所可能根本不能成为落点；应以统一接受查询替代“空闲桌牌”过滤 |
| 场所内部空间 | 当前仍是Active Staged列表加非活动Preparations，窗内显示只是重新排牌 | 缺真正槽位身份、逐槽命中、绑定/解绑、角色要求、占用状态和输出区域 |
| 入槽/取出/替换/转移 | 多个UI命令串联，部分动作瞬间改父级和位置 | 追卡槽AddEntityForm、场所RemoveEntity/OnDetached；定义单事务转移、可打断的运动与锁 |
| 持牌→可接收对象高亮 | 没有拖动会话广播候选；Related只来自当前组合预览 | 缺场所、卡槽、牌堆接受查询及共同拒绝原因，不是补一圈绿框 |
| 点空槽→可用牌高亮 | 没有可点击空槽组件，也没有槽身份查询 | 需要还原PlayerSelect事件接收端与槽条件，避免泄露未知配方 |

| 放入/弹出/弹飞/合并反馈 | 目前主要是新产物0.3秒飞行；普通位置在Render里直接赋值 | 追动态飞行动作、Animator与参数源；不要把所有运动当同一Tween |

| 暂停/菜单/失焦/销毁 | 有若干分散保护，不是已验证全链 | 需追取消与清理矩阵，保证归属不丢、动画不抢位置、暂停不相互覆盖 |
| 存档恢复整条桌面 | 现有档保存牌、任务和准备列表 | 堆、槽身份和连接没实现，当然无从正确保存；恢复后动效/候选重建也需设计 |
| 配置驱动与性能 | 有配方配置，桌面交互部分在View硬编码 | 补OverlapType/CardType/Slot配置解码；拖动候选不能每帧重建全桌；性能仍未实测 |

## 4. 重新挖掘的先后顺序与通过门槛

1. **第一条完整证据链**：InputMgr松手 → 命中真实资源点/槽位 → 接受查询 → 归属/父子变化 → 位置运动 → 取出逆过程。补齐接口/虚调用实际接收者和配置来源，不先照旧四级树写实现。
2. **双向提示链**：拖动事件→槽/资源点候选；槽位PointerUp→PlayerSelect→桌牌候选。记录两端所用条件是否一致，以及结束/取消如何撤销提示。
3. **牌堆链**：堆兼容与上限→挂接→拖起子树/单牌→移入场所时拆分或整组进入→任务占用→放出恢复。
4. **运动链**：展开动画绑定、抓取运动、收牌与返还、飞牌、碰撞推开；逐项记录输入、对象状态、参数来源、取消与结束状态。
5. **恢复链**：暂停、失焦、目标消失、读档、重开及对象复用。之后才按完整操作链安排实现。

每条通过需同时给出：来源资产pathID/字段、正确Token/VA、关键分支或调用证据、尚未识别的接口调用、对项目的落地边界。原作事实与本项目建议分栏；没有证据的规则写未知。本文也不冒称完整反编译或实机观察。
