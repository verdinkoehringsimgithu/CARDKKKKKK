# 操作验收矩阵

全部为待执行。本轮没有Unity运行结果。以下是本项目建议验收条件（D），不是原游戏观察记录。接手AI可据此准备可见的独立验收场景，由用户运行。

场景建议：一张有限桌面、两只独立手实例、资源点×2、生产点×2、可堆材料、不同耐久工具、带到期计时的食物、伤势牌、不可交互牌、一个可打开的模态窗。配置准备一个短采集和一个加工配方；时长为可修改验收值，不混入正式平衡。

| 编号 | 具体操作 | 应看见的结果/必须保持的状态 |
|---|---|---|
| V01 | 点击牌，再从牌边缘拖动 | 点按选中；超过阈值才拖动，抓取点不跳；牌被提到正确层级 |
| V02 | 拖动中按Esc，分别在桌外和模态窗上松手 | 会话结束，非法操作恢复原坐标/堆关系；无残留高亮与锁 |
| V03 | 在两张重叠牌与槽位交界处松手 | 候选预览与实际接受对象一致，目标选择符合已记录的规则 |
| V04 | 普通拖堆、修饰键拆牌、从中间取牌 | 按冻结的交互规则移动正确实例集合；每张牌只出现一次 |
| V05 | 合同类牌，拖到异类牌和已满堆 | 合法叠放有反馈；拒绝时不吞牌、不改原堆；计时和耐久仍独立 |
| V06 | 把不同磨损/到期进度的同类牌叠在一起再拆开 | 每实例保留原耐久和倒计时，存读后仍正确 |
| V07 | 拖牌到密集区、桌角、锁住的牌旁 | 按已明确策略重叠或有限避让；无持续抖动、穿出边界或无限弹飞 |
| V08 | 连续将十张产物投到狭窄区域 | 新牌可见、可取；无丢失、重生、不可达落点；空间不足给明确结果 |
| V09 | 将牌靠近吸附槽，再在边缘小幅移动、离开 | 显示候选并稳定吸附；离开解除；不来回闪烁或重复绑定 |
| V10 | 吸附目标关闭、销毁或进入不可用状态 | 连接按规则解除/保留，引用一致，无幽灵槽位 |
| V11 | 打开两个同类资源点，各投入一只手 | 各有独立槽位/进度/次数；没有全局准备区串料 |
| V12 | 从本地窗口关开、移动场所、再查看 | 窗口跟随/停留策略一致；任务状态不因UI重建丢失 |
| V13 | 将一只已投入的手用于第二个任务 | 拒绝重复占用，说明被何处占用；另一只手仍可用 |
| V14 | 悬停缺工具的输入槽，替换满足标签的工具 | 合适空闲牌高亮；不足/锁定牌不被误导；投入后提示及时更新 |
| V15 | 同一牌同时满足两个输入标签 | 不会一牌填两槽；数量不足明确指出；预览与开始结论一致 |
| V16 | 尝试未知组合，再解锁对应配方 | 未知前不暴露完整答案；解锁后出现正确引导；知识卡与规则一致 |
| V17 | 开始采集，再并行开始加工 | 场所处可看见占用与倒计时；投入实例可追踪；非占用牌仍可整理 |
| V18 | 计时结束，多种主副产物同时出现 | 从可辨认的来源弹出/飞出，落桌后可操作；牌数量等于已提交结果 |
| V19 | 执行期间取消，完成同一帧再取消 | 取消/完成只能有一个获胜；消耗和返还遵守明确策略，无复制 |
| V20 | 资源采尽后等待恢复 | 工作与恢复状态可辨；不能提前采集；恢复后次数/可用性同步 |
| V21 | 投入带到期时间的牌，准备、执行、退出分别等待 | 按孤岛设计准备阶段继续自身计时，执行阶段冻结；结束后正确恢复 |
| V22 | 暂停时整理、开窗、换配方；再恢复 | 核心时间/生物冻结，允许的整理可用；恢复不多结算一轮 |
| V23 | 用户暂停→打开菜单→失焦→回焦→关菜单 | 仍保持用户暂停；不会因关一个窗口解除其他暂停原因 |
| V24 | 拖动中缩放/平移桌面，滚动局部窗口 | 坐标不跳变；局部滚轮不穿透；镜头边界不把牌带丢 |
| V25 | 悬停长详情，拖牌穿过提示框/窗口关闭按钮 | 提示避边界，不挡关键操作；离开立即清理，不留下错误对象信息 |
| V26 | 动画中保存、读取、重开或退出 | 视觉可直接对齐快照；不靠动画回调补发物资；无迟到声音/幽灵牌 |
| V27 | 保存堆、槽、连接、两个并行任务与不同到期时间，再读档 | ID/位置/归属/剩余时间一致；任务只结算一次，所有引用可解析 |
| V28 | 读损坏/规则不兼容档 | 拒绝部分恢复并显示原因，保留当前已提交状态与原文件 |
| V29 | 拖动中目标被另一任务消耗/生物吃掉 | 松手重校验，安全拒绝或选择有效目标，无空引用和吞牌 |
| V30 | 隐藏/复用同一张牌和窗口多次 | 不继承上一次高亮、层级、进度、悬停、音效、回调或拖动偏移 |
| V31 | 1280×720、1600×900、1920×1080及宽屏打开场景 | 编辑态已有内容；整体适配；窗口/槽位/按钮可见可操作，不靠缩字救布局 |
| V32 | 返回原牌桌与法术拆装，再返回孤岛 | 原入口/牌堆/存档与当前状态保留；新模块不写旧玩法存档 |

## 性能单独记录

由用户实际运行后填写硬件、分辨率、构建/编辑器、牌数（例如100/300/1000）、可见窗口数、任务数、平均/峰值帧时间、GC分配和操作场景。数量只是采样点，不是未经测量的性能承诺。

重点：拖动命中查询、密集避让、候选高亮重算、批量出牌、场景重开后对象/材质/订阅增长。不要把“静态未发现全表扫描”当性能通过。
