# B04 - 物理叠牌、堆叠组织与实例守恒规范

> **规范等级**：
> - **E2 / D（牌堆拓扑组织与插入/拆堆算法规范）**：解决桌面卡牌在任意位置插入、多卡拆堆、堆叠上限控制以及不同耐久卡牌被错误抹平的核心逻辑问题。
> - **核心准则**：严禁把不同耐久/计时进度的卡牌抹平为纯数量；堆内父子关系绝对无环；单堆数量达到上限（MaxPileSize）时坚决拒绝并给出确定反馈。

---

## 一、牌堆线性列表拓扑与无环保证

在核心数据层，牌堆采用严密的单一父级线性列表拓扑结构：

```csharp
public sealed class PileData
{
    public string Id;                     // 堆唯一技术标识
    public TablePoint Position;           // 底牌左下角世界坐标
    public List<string> CardIds;          // 堆内卡牌实例 ID 列表 (从底到顶)
}
```

- **拓扑不变量（Invariant）**：
  1. 任意卡牌 $C$ 的 ID 必须且只能出现在全桌唯一一个 `PileData.CardIds` 列表中；
  2. 堆内卡牌不存在树状嵌套引用，彻底杜绝循环父子死锁（$A \to B \to A$）；
  3. 卡牌在堆内的纵向世界坐标由其下标 $i$ 唯一严格决定：
     $$X_i = Position.X, \quad Y_i = Position.Y + i \times PileOffset$$

## 二、任意位置插入算法（Precise Insertion）

当拖拽一组卡牌悬停于现有牌堆上方时，系统实时计算光标落点位于哪两张卡牌之间：

```csharp
public static int CalculateInsertionIndex(PileData targetPile, float pointerY, float pileBaseY, float pileOffset, float cardHeight)
{
    if (targetPile.CardIds.Count == 0) return 0;

    // 从顶到底逆向扫描每张卡牌的有效判定区域
    for (int i = targetPile.CardIds.Count - 1; i >= 0; i--)
    {
        float cardTop = pileBaseY + i * pileOffset + cardHeight;
        float cardBottom = pileBaseY + i * pileOffset;

        // 若光标落在当前卡牌的上半部分，插入在其上方 (i + 1)
        if (pointerY >= cardBottom + cardHeight * 0.5f)
            return i + 1;
    }
    // 落在底牌下半部，插入在最底部 (0)
    return 0;
}
```

- **视觉提示**：表现层实时在插入点绘制一条发光的水平插入指示线（`insertionLine`），松手时卡牌精准切入该位置，原上层卡牌平滑向上微抬腾出空间。

## 三、容量上限（MaxPileSize）与防御策略

1. **容量硬上限**：
   - 规则资产配置 `MaxPileSize`（默认 20 张）；
   - 判定公式：
     $$Count_{current} + Count_{incoming} \le MaxPileSize$$
   - 一旦超出，`QueryDrop` 立即返回 `IsValid = false`，错误码 `StackLimitReached`，并显示提示文案：“牌堆已达最大容量（20张）”；
2. **拒绝退路**：
   - 超出上限松手时，拖拽卡牌绝不发生覆盖，而是触发优先级 4 的“桌面自由避让落位”（在旁边生成新牌堆），绝不丢失卡牌。

## 四、实体属性守恒铁律（No Attribute Flattening）

许多卡牌游戏因为将相同定义的卡牌简单粗暴地用 `Count++` 合并，导致玩家精心打造的“高耐久石斧”和快坏掉的“残损石斧”合并后变成两把平均耐久的斧头，产生严重数值 Bug。

本项目严格执行**实体守恒铁律**：
- 合堆**只改变物理组织层叠关系**，每张卡牌依然保留其独立的 `CardInstanceId`、独立当前耐久 `Durability`、独立计时器 `TimerRemaining` 与独立关联伤势；
- 读档时，按照堆内顺序逐张还原各自独立属性，没有任何数据被损耗或平均化。
