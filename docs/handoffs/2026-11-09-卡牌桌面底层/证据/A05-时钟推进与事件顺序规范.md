# A05 - 时钟推进、事件确定性顺序与暂停策略规范

> **规范等级**：
> - **E2 / D（纯 C# 时钟调度与确定性事件流水线规范）**：定义核心时间流逝机制、多事件同帧并发时的严格确定性排序、多重暂停原因掩码与防重入读档机制。
> - **核心准则**：严禁使用 Unity 表现层 `Time.deltaTime` 或 Tween 回调作为核心逻辑计时；同一时间戳触发的多个事件必须具有全序确定性；暂停期间严禁任何逻辑时间流逝。

---

## 一、时钟核心推进模型（Clock Pipeline）

```mermaid
flowchart TD
    AdvanceCmd[执行命令: AdvanceClock(deltaMinutes)] --> CheckPause{PauseMask != 0 ?}

    CheckPause -- 是 (处于任一暂停状态) --> IgnoreAdvance[拦截推进: 返回 TableResult.Unchanged]

    CheckPause -- 否 (时间正常流逝) --> LoopMinutes[循环推进每一逻辑分钟 (Step Minute)]

    LoopMinutes --> P1[Phase 1: 生产与研究任务完成结算 (TaskCompleted)]
    P1 --> P2[Phase 2: 设施充能与冷却周期恢复 (RechargeRestored)]
    P2 --> P3[Phase 3: 桌面卡牌自身寿命/腐烂结算 (CardExpired)]
    P3 --> P4[Phase 4: 角色生理机能结算 (Hunger / San / 伤势恶化)]
    P4 --> P5[Phase 5: 生物与环境行为 (如雏鸟移动/潮汐演化)]

    P5 --> CheckMore{还有剩余 delta 分钟?}
    CheckMore -- 是 --> LoopMinutes
    CheckMore -- 否 --> CommitClock[原子提交新状态: Revision++, 发布 ClockTickedEvents]
```

## 二、同帧多事件严格确定性全序排序（Deterministic Total Ordering）

当在同一分钟内有多个事件到达结算阈值时，核心必须按固定阶段与二级稳定键排序，杜绝由哈希表遍历无序性导致的不可复现 Bug：

| 阶段顺序 | 事件类型 | 二级稳定排序键 (Secondary Sort Key) | 设计目的与业务理由 |
|:---:|---|---|---|
| **Phase 1** | 工作/配方任务完成 | `Job.Id` 升序 | 任务先交付，产出材料优先进入桌面，供后续阶段使用 |
| **Phase 2** | 设施充能/冷却恢复 | `Facility.Id` 升序 | 设施先恢复可用充能与冷却时间 |
| **Phase 3** | 卡牌自身寿命/腐烂 | `Card.InstanceId` 升序 | 桌面未锁定的生鲜材料发生腐败（被锁定的已在 A04 冻结） |
| **Phase 4** | 生存数值与伤势演化 | 固定：先扣饱食 -> 再结算精神 -> 最后伤势 | 生理指标严格按因果链传导，饱食不足才会加剧体能衰竭 |
| **Phase 5** | 移动生物巡游/觅食 | `Creature.InstanceId` 升序 | 环境生物在所有人事结算完成后最后行动（如雏鸟捕食落桌材料） |

## 三、多重暂停原因掩码（Pause Mask）

暂停状态不能是一个简单的布尔值 `isPaused`，否则当“玩家按空格暂停”后“打开设置菜单”，关闭设置菜单时就会错误地把玩家的全局暂停取消。

核心采用**按位掩码（PauseFlags）**：

```csharp
[Flags]
public enum PauseFlags
{
    None            = 0,
    ManualPause     = 1 << 0,  // 玩家主动按空格/点击暂停按钮
    ModalMenuOpen   = 1 << 1,  // 打开系统菜单/设置/剧情说明弹窗
    WindowBlur      = 1 << 2,  // 游戏窗口失去焦点/最小化
    DragProtection  = 1 << 3,  // 某些敏感模态拖拽期间的保护性暂停
    SceneTransition = 1 << 4   // 切场景/退出/读档中
}
```

- **生效规则**：只要 `CurrentPauseMask != PauseFlags.None`，时钟完全停滞；
- **独立解禁**：关闭弹窗仅移除 `ModalMenuOpen` 标志；若 `ManualPause` 仍然存在，游戏继续保持暂停。

## 四、读档与时间防溢出准则

1. **读档强制初始暂停**：
   - 任何本地存档恢复（`Restore`）成功后，游戏默认状态一律强制设为 `ManualPause` 生效；
   - 保证玩家进入游戏后有充分的时间观察当前桌面卡牌分布与任务倒计时，严禁读档瞬间时间突然飞奔。
2. **离线与断线零假定**：
   - 单机卡牌桌面不执行任何“离线挂机收益推算”；
   - 存档中保存什么时间戳和剩余分钟数，读档时就精确重现该数字，杜绝修改系统时间带来的坏档与死锁。
