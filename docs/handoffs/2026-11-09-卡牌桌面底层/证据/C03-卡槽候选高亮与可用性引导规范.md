# C03 - 卡槽候选高亮与可用性引导规范

> **规范等级**：
> - **E2 / D（智能引导与局部上下文高亮规范）**：实现基于槽位标签的精准卡牌高亮推荐，彻底废除粗暴的全桌无差别亮框，提供清晰直观的失配反馈。
> - **核心准则**：悬停卡槽时只高亮精确符合当前槽位条件的空闲卡牌；已占用、锁定中或坏死牌坚决不予推荐；投入或移除卡牌时光照状态毫秒级响应刷新。

---

## 一、局部精准高亮查询管线（Targeted Highlight Pipeline）

```mermaid
flowchart TD
    HoverSlot[光标悬停于卡槽: Slot.OnPointerEnter] --> GetSlotFilter[提取卡槽要求: RequiredDefinition / RequiredTags]

    GetSlotFilter --> ScanDesk[扫描桌面所有卡牌实例]

    ScanDesk --> Filter1{是否已被其它槽预留 (Card.BindingSlot)?}
    Filter1 -- 是 --> Exclude[排除: 不高亮]

    Filter1 -- 否 --> Filter2{是否处于任务锁定 (LockedByJobId > 0)?}
    Filter2 -- 是 --> Exclude

    Filter2 -- 否 --> Filter3{是否满足卡槽标签或定义?}
    Filter3 -- 否 --> Exclude

    Filter3 -- 是 --> Filter4{卡牌是否处于有效可用状态 (未损坏/未腐坏)?}
    Filter4 -- 否 --> Exclude

    Filter4 -- 是 (完全合格) --> MarkHighlight[加入高亮列表: ApplyGreenHighlight (#75FF29)]
```

---

## 二、三类无效卡牌严格排除准则

1. **已预留卡牌（Reserved Cards）**：
   - 已经在其它场所卡槽中等待开始的卡牌，必须排除，防止诱导玩家重复借用；
2. **任务加锁卡牌（Task Locked Cards）**：
   - 正在进行 3 分钟烧烤或研究的卡牌，无法被二次分配，坚决不高亮；
3. **身体坏死与状态异常牌（Incapacitated Body Parts）**：
   - 处于重度感染、骨折未复位的身体牌，在未接受医疗护理前，无法用于重体力采集槽位。

---

## 三、动态响应与交互反馈机制

1. **瞬时自适应刷新**：
   - 玩家一旦将一张卡牌拖入主槽，该场所的配方候选随之收窄，辅槽的条件相应发生改变，全桌高亮指示灯必须在同帧自动更新推荐列表；
2. **失配原因即时浮现**：
   - 当玩家试图把一块石头拖入只接受“木质材料”的卡槽上方时，槽位外框呈现排斥红色（`#FF391F`），并在卡槽底部弹出轻巧的文本气泡：“需要带有 [木质] 标签的材料”，玩家移开后即刻淡出。
