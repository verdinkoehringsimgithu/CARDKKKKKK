# C02 - 配方匹配算法、缺项判定与探索解锁规范

> **规范等级**：
> - **E2 / D（纯 C# 配方引擎与探索解锁规范）**：实现精准定义 ID、标签（Tags）、数量与状态的多维度配方匹配，保障预览与执行同源驱动，并对未知配方实行严格的信息保护。
> - **核心准则**：两输入槽绝对不能重复借用同一卡牌实例；预览器与核心执行器严格共用同一套匹配逻辑；未知配方坚决不提前泄露产出名称与图标。

## 一、配方匹配流水线与多槽无重叠约束

```mermaid
flowchart TD
    InputCards[收集场所当前各卡槽投入的卡牌实例] --> CheckDup{检查实例 ID 是否重复?}
    CheckDup -- 是 (同一实例重复投入多槽) --> FailDup[判定失败: 槽位实例冲突]

    CheckDup -- 否 (各槽实例唯一) --> MatchLoop[遍历该场所支持的配方库]

    MatchLoop --> MatchExact[1. 精确卡牌定义 ID 匹配 (CardId == rule.CardId)]
    MatchExact --> MatchTag[2. 标签能力匹配 (card.Tags.Contains(rule.Tag))]
    MatchTag --> MatchCondition[3. 状态与损耗检查 (耐久 > 0 / 未腐败)]

    MatchCondition --> EvalResult{是否所有必要槽位均已满足?}
    EvalResult -- 全部满足 --> MatchSuccess[匹配成功: RecipeMatch.Ready\n生成配方启动计划]
    EvalResult -- 部分满足 (缺少工具/材料) --> MatchIncomplete[部分满足: RecipeMatch.Incomplete\n生成具体缺项指引]
    EvalResult -- 均不满足 --> MatchNone[无匹配: RecipeMatch.None]
```

- **实例独立性铁律**：
  - 若配方要求两份“木材”，而玩家桌面上只有 1 块木材，即便该木材同时拥有 `Wood` 和 `Fuel` 标签，也**绝不能**同时填充材料槽 1 和材料槽 2。

## 二、未知配方与盲试探索保护（Blind Experimentation）

为维护卡牌生存游戏核心的探索乐趣，系统建立明确的知识解锁状态机：

| 配方状态 | 判定条件 | 界面可见信息 | 隐藏/保护信息 |
|---|---|---|---|
| **已知配方** (`Known == true`) | 配方初始公开，或玩家曾成功合成过一次 | 完整配方名称、所需耗时、主产物与副产物图标及概率 | 无 |
| **未知但可盲试** (`Known == false`) | 材料完全匹配，但玩家尚未解锁该知识 | 配方名称显示“??? 新的发现”、预计耗时与启动按钮 | **严格隐藏**：具体产出物名称、图标、数量与副产线信息 |
| **条件不足** (`Incomplete`) | 投入了部分有效材料，尚缺关键引子 | 已知配方显示缺项要求（如“缺少 [研磨] 工具”）；未知配方仅提示“似乎还缺少某种材料” | 未知配方不提前暴露配方全貌 |

- **解锁时机**：任务结算（`CompleteTask`）成功完成的那一刻，核心原子提交 `KnownRecipes.Add(recipe.Id)`，并通过事件流发布 `RecipeDiscoveredEvent`，表现层弹出新配方解锁动效。

## 三、副产线与辅助槽（Auxiliary Slots）联动

根据孤岛出航规则规范（32 条副产线）：
- 当配方主流程运转时，若辅助槽额外投入了特定催化剂/工具（如研磨石、防雨遮罩）：
- 匹配器自动激活对应的 `VoyageAuxiliaryRule`：
  - 缩短工作时间（`MinutesDelta < 0`）；
  - 提高产出倍率（`OutputMultiplier > 1`）；
  - 减少角色精神消耗或额外产出副产物。
