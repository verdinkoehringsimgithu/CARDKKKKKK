# A03 - 配置、读档与资产分工规范

> **规范等级**：
> - **E2 / D（工程规范与架构冻结）**：确立卡牌静态定义（`CardDefinition`）、行为规则配置（`TableRules` / `VoyageRules`）、交互表现主题（`TableTheme`）以及运行时存档（`SaveStore`）的四权分工。
> - **核心准则**：消除未实现字段；技术 ID 必须保持全局稳定；静态定义与动态实例彻底分离；读档执行严格版本迁移与图谱拓扑校验。

---

## 一、配置与资产的三权分工模型

```mermaid
flowchart LR
    subgraph StaticAssets [1. 静态策划资产 (ScriptableObject)]
        CardDef[CardDefinition: 固有属性/插画/音效/定义ID]
        RulesAsset[RulesAsset: 空间物理/堆叠限制/144条配方]
        ThemeAsset[TableTheme: 卡框/三色高亮/缓动时长/层级]
    end

    subgraph RuntimeEngine [2. 纯 C# 运行时核心 (Pure C#)]
        Catalog[CardCatalog: 只读字典索引]
        EngineState[TableState / VoyageState: 实例列表/堆叠/槽位绑定/时钟]
    end

    subgraph SaveDocument [3. 磁盘持久化文档 (JSON)]
        SaveFile[SaveFile: Envelope 包装 + 状态数据 + SHA256 + 规则指纹]
    end

    CardDef --> Catalog
    RulesAsset --> EngineState
    ThemeAsset -.-> View[表现层 View / Prefab]
    Catalog --> EngineState
    EngineState <--> SaveFile
```

### 1. `CardDefinition`（卡牌静态定义）
- **定义**：由策划在 Unity 编辑器中配置的 `ScriptableObject`，只记录卡牌类型固有属性。
- **允许字段**：
  - `Id`（string，全局唯一技术 ID，发布后永久固定）；
  - `DisplayName`（string，中文化界面展示名称，可自由调整不影响存档）；
  - `Family`（string，堆叠族系，如 `Material`、`Body`、`Tool`）；
  - `SortRank`（int，牌堆排序权值）；
  - `Tags`（`List<string>`，能力与配方标签，如 `Wood`、`Sharp`、`Limb`）；
  - `Artwork`（Sprite，卡面插画）；
  - `Description`（string，卡牌功能描述）；
  - `InitialAttributes`（默认初始耐久、初始充能等模板数据）；
  - `LegacyId`（string，旧版迁移 ID，仅用于读取旧存档）。
- **绝对禁止字段**：运行时坐标 `X, Y`、运行时堆归属 `PileId`、任务锁 `JobId`、当前剩余倒计时等。

### 2. 行为规则配置（`TableRules` & `VoyageRules`）
- 桌面物理尺寸：`Width`（1600）、`Height`（900）、`CardWidth`（100）、`CardHeight`（140）；
- 空间与堆叠规则：`MaxPileSize`（20）、`SnapDistance`（65）、`AllowStacking`、`StackRule`；
- 配方与时钟规则：`Recipes`（144 条输入/输出/概率/损耗）、`MinutesPerTick`、`DayNightCycles`。

### 3. `TableTheme`（交互与表现主题）
- 纯表现层配置，核心逻辑对其完全不可见；
- 视觉资产：默认卡框、卡背、暗色桌面底图、中文字体；
- 交互三色反馈（严格与 R01 证据一致）：
  - **默认常规色**：`#FFFFFF` (1, 1, 1)
  - **合法吸附/就绪色**：`#75FF29` (0.4588, 1, 0.1608)
  - **非法拦截/排斥色**：`#FF391F` (1, 0.2235, 0.1216)
- 动效时长：拖动跟随平滑时间（`0.12s`）、松手避让弹性（`0.25s`）、飞出动画时长（`0.35s`）。

## 二、稳定技术 ID 命名规范与别名迁移

1. **命名规范**：
   - 统一使用小写英文字母与下划线：`{category}_{name}`
   - 示例：`item_101`（防水涂料）、`body_hand`（手）、`facility_work`（工作台）、`recipe_explore_beach`（海滩探索）。
2. **显示名与技术 ID 解耦**：
   - 玩家看到的卡牌名称完全来自 `DisplayName`。本地化或改文案绝不修改 `Id`；
3. **别名迁移机制（Legacy Aliases）**：
   - 当老存档中出现过时的历史 ID 时，核心在加载时通过映射表（`LegacyIdMapping`）自动迁移为最新 ID，保证老玩家存档绝不崩溃。

## 三、存档文档规范与三级验证机制

### 1. 存档文档外壳（`SaveEnvelope`）
```json
{
  "Format": "CardKKK.SaveDocument",
  "Version": 1,
  "RulesFingerprint": "a3f81e...",
  "Payload": "{ ... 实际核心数据 JSON ... }",
  "Sha256": "7c8b21..."
}
```

### 2. 写入三阶段安全协议（Atomic Write Protocol）
1. **生成并校验 Payload**：将最新状态序列化并计算 SHA256 哈希；
2. **写入独立临时文件**：写入 `savefile.json.tmp` 并强制 `Flush(true)` 落盘；
3. **原子滚动替换**：
   - 若原存档存在且有效，自动将其替换为 `savefile.json.bak`（提供崩溃回滚保障）；
   - 将 `.tmp` 原子重命名为 `savefile.json`。

### 3. 读取三级严格校验
- **第一级（物理完整性）**：计算文件 SHA256 哈希，若哈希不符，自动尝试读取 `.bak` 备份文件；
- **第二级（规则指纹比对）**：若规则指纹变动（如删除了卡牌定义），核心触发平滑兼容升级处理器；
- **第三级（所有权拓扑完整性校验）**：
  - 检查所有卡牌 `InstanceId` 全局唯一；
  - 检查所有桌面卡牌严格属于单一 `Pile`，且牌堆内无循环引用；
  - 检查所有位于卡槽（`Slot`）的卡牌，其对应的场所实体必须存在；
  - 检查所有被 `JobId` 加锁的卡牌，其对应的任务必须在 `Jobs` 列表中有效存在；
  - 校验失败立即中止读取并给出具体错误，杜绝产生残缺的死锁脏数据。
