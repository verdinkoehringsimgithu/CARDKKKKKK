# Context Modeling

- Extract the requested outcome, domain objects, constraints, and relevant existing behavior from the request and available project context.
- Preserve the user's terminology and abstraction level. Do not expand a mechanic request into an architecture or a product redesign.
- Resolve important ambiguity from available evidence. State a reasonable assumption for reversible details; ask only when unresolved meanings materially change scope, behavior, or core design.
- Briefly explain consequential assumptions before acting. Do not require an interpretation table or a separate planning phase for a clear request.
