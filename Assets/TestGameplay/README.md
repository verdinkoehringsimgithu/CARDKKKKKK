# 测试玩法

原牌桌左上角的“测试玩法”按钮进入工艺工坊。“返回牌桌”会卸载工坊场景，恢复原牌桌对象；原控制器、卡牌、堆叠和位置仍保留。

## 实现边界

本模块不引用原牌桌程序集，不共享库存或存档。原场景只新增一个独立入口根对象，构建列表新增测试场景，原 Play 默认入口不变。测试玩法不包含发牌、翻面、洗牌、调序等操作，原牌桌继续拥有这些功能。

Core只有纯C#数据和规则。WorkshopEngine在候选状态完成校验、扣料、推进、产出和解锁后一次提交；视图只显示已提交状态。游戏分钟由操作推进，动画不改变库存。

## 修改入口

| 文件或目录 | 内容 |
|---|---|
| Configuration/测试工坊配置.asset | 物品、工位、插画、8条工艺、4项采集、字体和颜色 |
| Configuration/Scenarios | full完整流程、gray_a已有存炭、gray_b资源未备 |
| Core/WorkshopEngine.cs | 开工、采集、等待、恢复与目标结算 |
| Core/WorkshopEngine.Validation.cs | 配置与快照的集中校验 |
| Unity/WorkshopBootstrap.cs | 配置、命令、视图和存档的装配 |
| Unity/WorkshopView.cs | 选中、工艺比较、库存池和拖放筛选 |
| Unity/WorkshopSaveStore.cs | 新玩法自己的原子写入、摘要和备份恢复 |
| Unity/TestGameplayEntry.cs | 增量加载测试场景、停用及恢复原牌桌 |
| Prefabs/WorkshopView.prefab | 可直接编辑的测试界面布局与模板 |
| Prefabs/TestGameplayEntry.prefab | 原牌桌上独立的入口按钮 |
| Scenes/TestGameplay.unity | 工坊独立场景、相机与事件系统 |
| Art | SpriteCook物件图、卡框、字体与生成记录 |

Inspector字段是中文。实际工艺以资产为准，docs/design/首版配方草表.csv只供策划对照，不会自动覆盖配置。编辑配置后重新进入或重新开始；配方规则变更使旧测试存档被拒读，原文件保留。

本版工位和地点数量固定为两个、三个，其稳定ID不可改名；可修改显示名、插画、采集产量、耗时和关联工艺。新增物品与同工位配方可从配置列表扩展；增加第四地点或第三工位需要同步改场景布局，不能只加一条未显示的配置。

完整开局的目标是制造铜斧后采集一次木料。灰盒仅开放快烧、封窑、炉衬和两种熔铜，送坩埚，目标铜锭3；切换总配置的默认开局ID选择它们。

## 存档和原牌桌

测试文件在 Application.persistentDataPath/TestGameplay 下，按开局分别保存。旧 card-table.json 与其备份不在本模块的读写路径内。返回及退出会保存测试状态；进入时恢复对应开局存档。读取失败不改变当前状态；初次恢复失败时暂停自动保存，直到手动保存或明确重新开始，避免覆盖之前的进度。

原牌桌根对象在测试期间停用，原输入、相机、事件系统和监听器同时暂停；测试场景有自己的一套组件。返回时先停用测试对象，再卸载场景，最后恢复原牌桌。只有直接打开测试场景、没有原牌桌可恢复时，“返回”才重新打开默认牌桌。

## 本轮核对范围

检查了源码接口、场景与Prefab引用、配置数值、程序集依赖、美术Sprite和字体元数据。对照过纸面流程；没有执行编译、Unity、游戏测试或性能测试，不能据此称运行通过。

用户首次实际运行暴露出两个布局错误：工艺行被纵向布局压成零宽，卡名/数量被Noto字体行高裁切。已在Prefab内修正横向拉伸和文字框高度，并为加工的两行状态留出高度。另将测试场景本地对象ID分配到独立大整数区间，保留所有外部资源ID与GUID；它用于排除加载时的fid断言风险，尚未由后续实际运行确认。
