# 法术拆装

用户于2026-11-05选择这一方向并授权实现。入口为原牌桌左上角“测试玩法”，实际场景为Scenes/Spellcraft.unity，界面在Prefabs/ForgeView.prefab，编辑状态下已有完整桌面和装置。

## 开始玩

1. 点击三个装置中的任意一个，选择触发、效果、改装零件，再点“装上”。已掌握的零件方案可以重复使用，拆装不消耗库存。
2. 点“进入试炼”。先选敌人，再点击手牌或手动装置。悬停可看实际候选结算，包括连锁后的生命、护盾、火花和敌人状态。
3. 点“结束回合”。燃烧先结算，敌人再按预告行动，随后能量补满、护盾归零、弃手抽牌。火花可留到下回合。
4. 前三场胜利各选一个新零件，恢复9生命，回装配台重接；第四场胜利完成本轮试炼。失败可重新开始。

键盘：Q/W/E对应三个装置，1～5对应手牌，空格结束回合，回车确认焦点按钮。自动装置由条件启动，不用点。Esc关闭拆装页，或开关菜单；保存、读取、重开和返回牌桌都在菜单里。返回保留原牌桌的牌与摆放。测试场景使用独立SpellcraftSubmit输入轴，回车确认与空格结束回合分开，原牌桌输入保持原有绑定。

目标点击通过核心SelectEnemy命令生效并保存，自动触发、预演、目标框与读档使用同一份目标状态。切换目标不耗能量或火花，不推进随机数。

## 规则

开局42生命，每回合3能量，每场起始3火花，上限12。每个装置每回合最多启动两次。手动启动另花1能量；每次启动都支付效果的火花费用。先付费、占次数，再依序结算资源事件和效果，自动装置也可能触发其他装置。火花不足或次数已满会跳过并说明原因。

默认三个装置：手动启动→电击器；受伤触发→充能器；耗火花触发→护盾器。第一发手动电击按规则总共花3火花，造成4伤并取得8盾，护盾器自触发两次后达到上限。也可以改成格挡充能、消耗火花后点燃、手动叠盾等路线。

燃烧直接扣生命、绕过护盾且不反射，结算后层数减1。冻结跳过敌人行动，层数减1、原意图保留。反伤飞蛾每次遭到直伤都会反射，包括致命命中；双方同时倒下判玩家失败。吸血按实际造成的生命伤害治疗，不能救活已经倒下的玩家。

“全体作用”使攻击或异常作用全部敌人；“重复两次”使效果执行两次。两者每次强度减1、最低1。“增强输出”额外花1火花、强度加2。每个装置仍受同一次数上限约束。

四场为机械甲虫、反伤组合、火花干扰、强化组合。奖励分别提供全体作用/冷冻器/回合开始、重复两次/吸血器/燃烧触发、增强输出/重型电击器/备用电池的三选一。初始九种已掌握零件，加前三场选择，共有18种零件定义。基础手牌只有敲击、防御、充能、点燃、全部放电五种；更复杂的效果来自玩家装配。

## 界面

桌面采用1600×900逻辑尺寸，按可用安全区整体等比缩放，宽屏或较高窗口的剩余区域保留背景。当前面向Windows桌面，按1280×720及以上使用；更小窗口会继续缩放，但不保证文字阅读舒适度。

顶部只放当前关卡、回合、资源和菜单。中间依次为敌人和反馈区、三个装置、手牌或备战按钮。敌牌、手牌固定比例，横向容器不拉伸卡片；横向装置和零件列表改用平面信息板，避免把竖卡框压扁。

拆装时隐藏主桌面，三列零件分别滚动；底部保留组合、费用与完整规则的滚动区，确认与清空按钮独立摆放。提示条使用列表与底栏之间的空隙。战斗时悬停牌或装置，右侧保留最近一次完整候选预演，鼠标移到该区可滚动；使用行动或切换目标时重新刷新。连锁记录最多显示七条短事件。

修改直接保存到Prefabs/ForgeView.prefab，不在运行时重造桌面。调整后停止当前Play并重新进入“测试玩法”加载新结构；原牌桌无需重新搭建。

## 配置与代码

“测试玩法/法术工坊规则”打开Configuration/法术工坊配置.asset，中文Inspector配置内容。数值与解锁来自此资产；不从README或旧CSV读取。界面当前固定三装置，支持1～5手牌、最多3敌人、最多3奖励选项；扩大数量应先改Prefab池，再调整配置边界。

- Core/ForgeData.cs：纯数据。ForgeCopies.cs：深拷贝。
- Core/ForgeEngine.cs：命令、确定性FIFO事件队列、受限触发、牌堆随机状态、阶段流转、完整候选预演。
- Core/ForgeEngine.Validation.cs：配置和恢复语义校验。
- ForgeConfiguration.cs：Unity资源与纯规则桥接。
- Unity/ForgeBootstrap.cs：唯一命令入口、存档与返回，不生成UI。
- Unity/ForgeView.cs及两类卡视图：显示快照、发送意图、播放已提交的事件。
- Unity/ForgeDesktopLayout.cs：编辑态与运行态共用的逻辑桌面等比缩放；安全区、比例视口、逻辑内容分别处理，不让多个组件同时驱动同一个RectTransform。
- Unity/ForgeSaveStore.cs：规则指纹、SHA256、2MB限制、原子写和有效备份；文件名spellcraft-v1.json，封装版本为2。新版规则指纹排除名称、说明与插画；PreviousPresentation.json只用于校验本次改名前的v1指纹，不参与当前玩法规则，不回退数值。

预演与实际命令共用同一候选结算；预演不提交、不推进随机、不发状态通知。真正命令只有在整条事件链与语义校验成功后提交；失败不扣费用、不弃牌、不留下部分战果。三装置和小牌组直接用字典查定义、FIFO队列排事件，无ECS或通用脚本语言。

每个装置的次数上限防止无限触发；另有单次事件预算作为错误防护，超预算整次撤回。冻结与重复两次可能形成长期控制，这是待实际体验调整的平衡点，不能据静态检查宣称所有组合平衡。

本轮未启动Unity、编译器或游戏测试。素材与序列化引用静态核对不等于实际运行通过。
